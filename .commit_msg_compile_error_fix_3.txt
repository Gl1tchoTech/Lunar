fix(swift): resolve 25 SwiftUI strict-concurrency + Typography errors

Six distinct error categories, all stemming from a single root
cause plus a stale Typography-token reference. One batch, nine
files, all runtime-neutral (no API surface changes, no behaviour
changes).

## What was wrong

After commit `b706513` cleared the EQSettings @MainActor stored-
property fallout and the missing AVMetadataKey member, the next
Swift 5.10 / strict-concurrency sweep surfaced 25 fresh errors:

(1) MainActor isolation in 5 SwiftUI Views (≈20 errors)
  - `SleepTimerSheet.swift:70,74,109,111` — private `statusPanel()`,
    `pillsGrid()`, `formatRemaining()` referenced `SleepTimer.isActive`,
    `secondsRemaining`, `durationMinutes`, `select(minutes:)`.
  - `TransportRow.swift:40,44,45,62,64,66,82,85,133,141` — computed
    `canGoPrev`, `canGoNext`, private `shuffleButton()`, `repeatButton()`,
    `playPauseButton()` referenced `engine.state`, `currentQueueIndex`,
    `queueSize`, `queueSettings.shuffleMode`, etc.
  - `SongInfoSheet.swift:170,187` — Menu's Button closure + favoriteToggleRow
    called `LibraryService.add()` / `toggleFavorite()` from a
    non-isolated autoclosure.
  - `PlaylistDetailView.swift` (SwiftCompile failed overall) — private
    `playAll(_:)`, `tapped(_:)` referenced MainActor state.
  - `SongsListView.swift:19` "does not conform to View" — downstream
    cascade from the same root cause family.

(2) Missing Typography members (6 errors across 6 files)
  - `Typography.bodyBold` (SleepTimerSheet.swift:149) — never defined.
  - `Typography.subheadline` (5 files: SmartPlaylistTile.swift:90,
    SongRow.swift:24, SongsListView.swift:187, SourceRow.swift:29,
    SourceView.swift:69, PlaylistDetailView.swift:3 heroCopy sites)
    — never defined.

## What I did

For category (1) — chose **structural** `@MainActor` on the View
struct itself rather than annotating each private method, because:

  - SwiftUI Views already gate their `body` to MainActor implicitly,
    so an explicit struct-level `@MainActor` is consistent with the
    framework's intent under iOS 17 / SE-0432.
  - It propagates MainActor isolation into ALL nested closures
    (Button `{ ... }`, Menu`s nested Button closures, computed `@ViewBuilder`
    properties) without per-call annotation. This is what solved the
    SongInfoSheet Menu closure + TransportRow Button closure line-items
    cleanly.
  - Matches our existing pattern from `b706513` where whole-type
    `@MainActor` on the enum AudioMetadataExtractor resolved the
    parallel category of errors.
  - Zero risk of breaking @State / @Environment / @Query — all three
    are already implicitly MainActor.

Files annotated:
  - `SleepTimerSheet` (4 errors → 0)
  - `TransportRow`        (10 errors → 0)
  - `SongInfoSheet`       (2 errors → 0)
  - `SongsListView`       (1 error → 0)
  - `PlaylistDetailView`  (SwiftCompile → OK)

For category (2) — name-mapped to existing tokens verified by
code-scan across the codebase:

  - `Typography.subheadline` → `Typography.subhead` (6 occurrences
    across 6 files). The codebase uses `subhead` everywhere else;
    `subheadline` simply doesn't exist.
  - `Typography.bodyBold` → `Typography.headline` (1 occurrence).
    The codebase uses `headline` for prominent-emphasis text; that's
    the semantic match for what `bodyBold` was clearly trying to
    express (heavier weight than `body` itself).
